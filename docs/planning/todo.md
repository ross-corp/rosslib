## API & Performance

- [ ] Log error from silent notification save in ToggleReviewLike: in `api/handlers/reviewlikes.go`, the `ToggleReviewLike()` handler sends a `review_liked` notification in a goroutine but discards the save error at line ~112 with `_ = app.Save(notif)`. If the notification fails to save, the user who liked a review gets no feedback and the review author never receives the notification. Add error logging: `if err := app.Save(notif); err != nil { app.Logger().Error("ToggleReviewLike: failed to save notification", "error", err) }`.
- [ ] Add panic recovery to mention notification goroutine: in `api/handlers/threads.go`, the `AddComment()` handler calls `go fanOutMentionNotifications(app, user, thread, rec.Id, data.Body)` (around line 361) without panic recovery. If `fanOutMentionNotifications` panics (e.g. nil pointer on a malformed mention), the goroutine crashes silently with no logging. Wrap in: `go func() { defer func() { if r := recover(); r != nil { app.Logger().Error("panic in fanOutMentionNotifications", "error", fmt.Sprintf("%v", r)) } }(); fanOutMentionNotifications(app, user, thread, rec.Id, data.Body) }()`.
- [ ] Trim whitespace from thread title and body in CreateThread: in `api/handlers/threads.go`, the `CreateThread()` handler (around line 136-151) validates that `title` and `body` are non-empty but does not trim whitespace before the check. A title of `"   "` (all spaces) passes validation and creates a thread with a blank-looking title. Add `data.Title = strings.TrimSpace(data.Title)` and `data.Body = strings.TrimSpace(data.Body)` before the empty checks. This matches the trimming pattern already tracked for `display_name`, `bio`, and other text fields.
- [ ] Trim whitespace from `proposed_note` in ProposeLinkEdit: in `api/handlers/links.go`, the `ProposeLinkEdit()` handler (around line 283-295) validates `proposed_note` length against 1000 chars but does not trim whitespace first. A note of 999 spaces followed by one character would pass the length check. Add `data.ProposedNote = strings.TrimSpace(data.ProposedNote)` before the length validation. Also add a check that at least one of `proposed_type` or `proposed_note` differs from the current values — currently a user can submit an edit that changes nothing.
- [ ] Trim whitespace from `query` field in CreateSavedSearch: in `api/handlers/searches.go`, the `CreateSavedSearch()` handler requires `query` to be non-empty but does not trim whitespace before the check. A query of `"   "` (all spaces) passes validation and creates a saved search that returns no results when clicked. Add `data.Query = strings.TrimSpace(data.Query)` before the empty check, matching the trimming pattern used elsewhere.


## API & Data Integrity

- [ ] Validate `link_type` against allowed values in CreateBookLink: in `api/handlers/links.go`, the `CreateBookLink()` handler accepts a `link_type` field but does not validate it against the allowed values (`sequel`, `prequel`, `companion`, `mentioned_in`, `similar`, `adaptation`). Add a whitelist check: if the provided `link_type` is not in the allowed set, return `400 { "error": "Invalid link type. Must be one of: sequel, prequel, companion, mentioned_in, similar, adaptation" }`. Currently any string is accepted and stored, which could cause display issues on the frontend.
- [ ] Add `upper_bound` validation for pagination offset in GetAuthorDetail: in `api/handlers/books.go`, the `GetAuthorDetail()` handler validates that `offset >= 0` but does not enforce an upper bound. A request with `offset=999999999` would pass validation and be forwarded to Open Library, potentially causing timeouts or unexpected behavior. Add a check: if `offset > 10000`, return `400 { "error": "Offset must be 10,000 or fewer" }`. Apply the same pattern to `GetFollowedBooks` and `GetFollowedAuthors` which also accept unbounded offset parameters.
- [ ] Add `limit` upper bound to GetUserBooks: in `api/handlers/userbooks.go`, the `GetUserBooks()` handler defaults `limit` to 8 when it's 0 or negative but does not cap it at a maximum. A request with `limit=100000` would attempt to return all books in a single response. Add a check: if `limit > 100`, cap it to 100. This matches the max limit pattern used in `GetFollowedBooks` (max 50) and `GetBookEditions` (max 100) and prevents excessively large responses.
- [ ] Add `rating` bounds validation to UpdateShelfBook: in `api/handlers/collections.go`, the `UpdateShelfBook()` handler accepts a `rating` field and sets it on the `collection_items` record without validating its range. Add a check: if `rating` is provided and (`rating < 1 || rating > 5`), return `400 { "error": "Rating must be between 1 and 5" }`. This matches the validation pattern used in `api/handlers/userbooks.go` `UpdateBook()` for book ratings and prevents invalid data in the collection_items table.
- [ ] Clean up book_links and book_link_votes when deleting a book from library: in `api/handlers/userbooks.go`, the `DeleteBook()` handler (around line 219) cleans up tag assignments, collection items, genre ratings, review likes, book follows, quotes, reading sessions, and review comments — but does NOT delete the user's `book_links` (links they submitted), `book_link_votes` (votes they cast), or `book_link_edits` (edits they proposed) for that book. After the existing cleanup, add: delete from `book_link_votes` where `user_id = userId` and the `book_link_id` references a link involving this book; delete from `book_link_edits` where `user_id = userId` and the `book_link_id` references a link involving this book. For `book_links`, soft-delete (set `deleted_at`) any links where `user_id = userId` and either `from_book_id` or `to_book_id` matches. This prevents orphaned link data when a user removes a book.
- [ ] Log errors from silent tag deletion in SetBookTag: in `api/handlers/tags.go`, the `SetBookTag()` handler (around line 286-294) deletes existing tags before creating new ones with `_ = app.Delete(a)`, discarding errors. If the delete fails but the new tag creation succeeds, the user ends up with duplicate tag assignments. Replace `_ = app.Delete(a)` with `if err := app.Delete(a); err != nil { app.Logger().Error("SetBookTag: failed to delete existing tag", "error", err) }`. The handler should continue to best-effort create the new tag but log the error for debugging.
- [ ] Add `series_name` max length validation to AddBookToSeries: in `api/handlers/series.go`, the `AddBookToSeries()` handler accepts a `series_name` field with max 255 chars (line 317-321) and a `position` field, but does not validate that `position` is non-negative. A negative position value would be stored in `book_series.position`. Add a check: if `data.Position != nil && *data.Position < 0`, return `400 { "error": "Position must be 0 or greater" }`.
- [ ] Log errors from silent genre rating saves in SetGenreRatings: in `api/handlers/genreratings.go`, the `SetGenreRatings()` handler calls `_ = app.Save(rec)` (around line 159) for each genre rating, discarding save errors. If a save fails, the rating is lost silently and the user believes it was saved. Replace with `if err := app.Save(rec); err != nil { return e.JSON(http.StatusInternalServerError, map[string]any{"error": "Failed to save genre rating"}) }`. This ensures the user gets feedback when a save fails rather than silently losing data.
- [ ] Log errors when local book search fails in SearchBooks: in `api/handlers/books.go`, the `SearchBooks()` handler runs a local catalog search alongside the Open Library search, but silently ignores errors from the local query (`localBooks, _ := ...`). Add `app.Logger().Error("local book search failed", "error", err)` when the local query fails so database issues are visible in logs. The search should still fall back gracefully to OL results, but the error should be logged for debugging. Apply the same logging to the `allStats, _ := ...` call that loads book stats.
- [ ] Validate `position` is non-negative in AddBookToSeries: in `api/handlers/series.go`, the `AddBookToSeries()` handler accepts a `position` field as an optional integer pointer but does not validate that it's non-negative. A negative position value like `-5` would be stored in `book_series.position`, which doesn't make semantic sense for a book's position in a series. Add a check: `if data.Position != nil && *data.Position < 0 { return e.JSON(http.StatusBadRequest, map[string]any{"error": "Position must be 0 or greater"}) }`.
- [ ] Validate `authorName` length in GetAuthorSeries: in `api/handlers/series.go`, the `GetAuthorSeries()` handler (around line 49-53) trims the `authorName` query parameter but doesn't validate its length. An extremely long author name is used in a `LIKE` query (`%name%`), which could be inefficient or abusive. Add a check: `if len(authorName) > 500 { return e.JSON(http.StatusBadRequest, map[string]any{"error": "Author name too long"}) }` after trimming.
